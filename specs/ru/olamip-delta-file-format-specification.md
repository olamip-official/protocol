# Спецификация формата файлов OLAMIP-DELTA

*Copyright © 2025 Ralph Gonzalez – https://olamip.org*

Протокол OLAMIP-DELTA определяет формат дельта-файлов на базе JSON для инкрементальных обновлений `olamip.json`. Эта спецификация предназначена для веб-мастеров и разработчиков, знакомых со структурированными данными, HTML и публикацией в стиле sitemap.

## 1. Обзор

`olamip.json` является авторитетным полным снимком (snapshot) структуры и содержимого вашего сайта. `olamip-delta.json` — это опциональный сопутствующий файл, описывающий изменения в этом снимке с момента последнего обновления.

Вместе они формируют интерпретируемый машиной поток изменений:

- `olamip.json`: полный структурированный снимок.
- `olamip-delta.json`: журнал инкрементальных изменений.

---

## 2. Основные концепции

- **Entry** — конечный элемент контента (например, статья в блоге, страница продукта, страница документации).
- **Section / Subsection** — иерархическая группировка (например, категория блога, категория документации, коллекция продуктов, группа проектов).
- **Operation** — одна из команд: `added`, `updated`, `removed`.
- **Delta** — набор изменений, привязанный к дате, содержащий списки `added`, `updated` и `removed`.

---

## 3. Расположение файла и обнаружение

### 3.1 Расположение файла

Файл olamip.json должен размещаться в корне вашего домена:
https://yourdomain.com/olamip.json

Файл olamip-delta.json должен находиться в той же директории:
https://yourdomain.com/olamip-delta.json

Версионные дельты (опционально) располагаются там же:
/olamip.json
/olamip-delta-YYYY-MM-DD.json

### 3.2 Механизм обнаружения

Веб-мастеры должны объявить местоположение olamip.json, используя оба тега в секции <head> сайта:

<link rel="olamip" href="https://yourdomain.com/olamip.json">
<meta name="olamip-location" content="https://yourdomain.com/olamip.json">

---

## 4. Структура верхнего уровня

На верхнем уровне olamip-delta.json представляет собой JSON-объект со следующими полями:

{
  "protocol": "OLAMIP-DELTA",
  "version": "1.0.0",
  "window_days": 7,
  "last_updated": "2026-04-28",
  "deltas": [
    {
      "date": "2026-04-27",
      "added": [
        {
          "title": "Example entry",
          "url": "https://example.com/page/",
          "summary": "...",
          "content_type": "blog_article"
        }
      ],
      "updated": [
        {
          "url": "https://example.com/page/",
          "summary": "Updated summary"
        }
      ],
      "removed": [
        {
          "url": "https://example.com/removed-page/"
        }
      ]
    }
  ]
}

### 4.1 Обязательные поля верхнего уровня

- protocol (string, обязательно): Должно быть "OLAMIP-DELTA".
- version (string, обязательно): Должно соответствовать схеме версий (напр., "1.0.0").
- window_days (integer, опционально): Количество дней в скользящем окне.
- last_updated (string, обязательно): Дата последнего изменения (ISO-8601).
- deltas (array, обязательно): Массив объектов дельты с полями date, added, updated и removed.

---

## 5. Структура объекта дельты

Для консистентности веб-мастеры ОБЯЗАНЫ включать все три поля операций (added, updated, removed) в каждый объект дельты, даже если некоторые из них пусты.

---

## 6. Операции

### 6.1 added
Элемент в added — это полный объект (запись, раздел или подраздел). Поля должны соответствовать спецификации формата OLAMIP.

### 6.2 updated
Элемент должен включать url и может быть либо частичным объектом (только измененные поля), либо полным объектом.

### 6.3 removed
Удаляемый элемент содержит только url:
{ "url": "https://example.com/page/to-remove/" }

---

## 7. Идентичность объектов
OLAMIP-DELTA использует канонические URL в качестве основного идентификатора. Смена URL требует операции удаления (remove) с последующим добавлением (add).

---

## 8. Скользящее окно дельты (Рекомендуется)
В этой модели файл содержит изменения за последние window_days (обычно 7–30 дней). Это основной режим, гарантирующий, что ИИ не пропустит обновления.

---

## 9. Версионные дельты (Альтернатива)
Допускается использование отдельных файлов для каждой даты: olamip-delta-YYYY-MM-DD.json. Системы ИИ должны сканировать директорию и применять их в хронологическом порядке.

---

## 10. Структурные изменения
Те же правила добавления, обновления и удаления применяются к разделам (sections) и подразделам (subsections). При удалении раздела все его потомки логически считаются удаленными.

---

## 11. Соответствие спецификации (Conformance)

### 11.1 Правила MUST
- protocol: "OLAMIP-DELTA".
- Поля added, updated, removed должны присутствовать всегда.
- URL должны быть абсолютными и каноническими.
- deltas отсортированы по дате (по возрастанию).

---

## 12. Лучшие практики
1. Автоматизируйте генерацию дельт через CMS.
2. Всегда поддерживайте актуальность основного файла olamip.json.
3. Используйте стабильные URL.
