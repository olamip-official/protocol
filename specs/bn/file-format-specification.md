## ওভারভিউ

`/olamip.json` হলো একটি কাঠামোবদ্ধ JSON ডকুমেন্ট যা আপনার ওয়েবসাইটের সবচেয়ে গুরুত্বপূর্ণ পৃষ্ঠাগুলোর সংক্ষিপ্ত, নির্বাচিত সারাংশ প্রদান করে। এটি বড় ভাষা মডেলগুলোর (LLMs) জন্য সহজে পার্সযোগ্যভাবে ডিজাইন করা হয়েছে, যাতে তারা আপনার কনটেন্টকে স্পষ্টতা, নির্ভুলতা এবং উদ্দেশ্যসহ বুঝতে, অগ্রাধিকার দিতে এবং ব্যবহার করতে পারে।

---

## ফাইলের অবস্থান

OLAMIP ফাইলটি অবশ্যই আপনার ডোমেইনের রুটে হোস্ট করতে হবে:

`https://yourdomain.com/olamip.json`

---

## OLAMIP ফাইলের অবস্থান ঘোষণা করা

সর্বোচ্চ গ্রহণযোগ্যতা নিশ্চিত করতে এবং সিস্টেমগুলো যাতে নির্ভরযোগ্যভাবে আপনার OLAMIP ফাইল খুঁজে পায়, আপনার সাইটের `<head>` সেকশনে `<link>` এবং `<meta>`—উভয় ট্যাগই প্রকাশ করুন।

### প্রাথমিক ডিসকভারি: `<link rel="olamip">`

- স্ট্যান্ডার্ড প্র্যাকটিস: ক্রলাররা ইতিমধ্যেই canonical, sitemap, alternate ইত্যাদির জন্য `<link>` স্ক্যান করে।  
- মেশিন‑ফ্রেন্ডলি: পেজ এবং OLAMIP ফাইলের মধ্যে আনুষ্ঠানিক সম্পর্ক ঘোষণা করে।  
- ইন্টারঅপারেবিলিটি: বিদ্যমান ওয়েব স্ট্যান্ডার্ডের সাথে সামঞ্জস্যপূর্ণ, AI সিস্টেমের জন্য গ্রহণ সহজ করে।

### ফallback ডিসকভারি: `<meta name="olamip-location">`

- মানব‑পাঠযোগ্য: ওয়েবমাস্টারদের জন্য সহজ।  
- সামঞ্জস্যতা: কিছু টুল `<meta>` স্ক্যান করতে পছন্দ করে।  
- রিডান্ডেন্সি: যদি কোনো ক্রলার `rel="olamip"` সমর্থন না করে, এটি ব্যাকআপ হিসেবে কাজ করে।

### কেন উভয় একসাথে ব্যবহার করা উত্তম

- ভবিষ্যৎ‑প্রমাণ: বিভিন্ন সিস্টেম ভিন্নভাবে ডিসকভারি বাস্তবায়ন করতে পারে।  
- স্থিতিস্থাপকতা: একটি ব্যর্থ হলে অন্যটি কাজ করবে।  
- ইন্টিগ্রেশন সহজ: ডেভেলপাররা তাদের পাইপলাইনের জন্য উপযুক্ত পদ্ধতি বেছে নিতে পারে।  
- স্পষ্টতা: দ্বৈত সংকেত OLAMIP ফাইলের অবস্থানকে স্পষ্ট করে।

### বেস্ট প্র্যাকটিস ইমপ্লিমেন্টেশন

```html
<link rel="olamip" href="https://yourdomain.com/olamip.json">
<meta name="olamip-location" content="https://yourdomain.com/olamip.json">
```

উভয় ট্যাগ ব্যবহার করলে আপনার OLAMIP ফাইল সর্বাধিক সংখ্যক ক্রলার, ভ্যালিডেটর এবং AI সিস্টেমের কাছে আবিষ্কৃত হবে।

## ফাইল স্ট্রাকচার

OLAMIP ফাইলটি অবশ্যই একটি বৈধ UTF‑8 এনকোডেড JSON ডকুমেন্ট হবে, যাতে থাকবে:

- `protocol`  
- `version`  
- `identity`  
- `content`  
- `metadata`  

### উচ্চ‑স্তরের স্ট্রাকচার

```json
{
  "protocol": "OLAMIP",
  "version": "1.0.0",
  "identity": { "...": "..." },
  "content": { "...": "..." },
  "metadata": { "...": "..." }
}
```

## Identity অবজেক্ট

| Field | Type | Required | Description |
|---|---|---:|---|
| `name` | `string` | Yes | ওয়েবসাইট বা প্রতিষ্ঠানের নাম। |
| `type` | `string` | Yes | সত্তার ধরন—যেমন `company`, `blog`, `ecommerce`। |
| `canonical_description` | `string` | Yes | সাইটের মানব‑পাঠযোগ্য বিবরণ। |
| `tags` | `array<string>` | No | ডোমেইন বা ইন্ডাস্ট্রি বর্ণনা করা ঐচ্ছিক কীওয়ার্ড। |

## Content অবজেক্ট

`content` অবজেক্টে থাকে:

- একটি `overview`  
- `sections` এর তালিকা  
- প্রতিটি সেকশনে `subsections` থাকতে পারে  
- প্রতিটি সেকশন বা সাবসেকশনে `entries` থাকতে পারে  

এটি বহু‑স্তরের হায়ারার্কি সমর্থন করে।

### Overview অবজেক্ট

| Field | Type | Required | Description |
|---|---|---:|---|
| `summary` | `string` | Yes | ওয়েবসাইটের উদ্দেশ্যের সংক্ষিপ্ত ব্যাখ্যা। |

## Section অবজেক্ট স্পেসিফিকেশন

একটি `Section` হলো কনটেন্টের একটি ক্যাটাগরি বা গ্রুপিং। এতে থাকতে পারে:

- `entries`  
- `subsections`  

### Section Fields

| Field | Type | Required | Description |
|---|---|---:|---|
| `title` | `string` | Yes | সেকশনের মানব‑পাঠযোগ্য নাম। |
| `summary` | `string` | Yes | সেকশনটি কী ধারণ করে তার বিবরণ। |
| `url` | `string` | Yes | সেকশনের canonical URL। |
| `section_type` | `string` | Yes | ট্যাক্সোনমি অনুযায়ী সেমান্টিক শ্রেণিবিভাগ। |
| `policy` | `string` | No | `"allow"` বা `"forbid"`। |
| `tags` | `array<string>` | No | ঐচ্ছিক কীওয়ার্ড। |
| `priority` | `string` | No | `"high"`, `"medium"`, `"low"`। |
| `published` | `string` | No | ISO 8601 তারিখ। |
| `language` | `string` | No | BCP‑47 ভাষা কোড। |
| `entries` | `array<Entry>` | Yes | Entry অবজেক্টের অ্যারে। |
| `subsections` | `array<Section>` | No | নেস্টেড Section অবজেক্টের অ্যারে। |

## Policy আচরণ ও ইনহেরিটেন্স

`policy` নির্ধারণ করে AI সিস্টেম কোনো Section, Subsection বা Entry ingest করতে পারবে কি না।

### ডিফল্ট আচরণ

`policy` না থাকলে ইনহেরিটেন্স অনুযায়ী মান নির্ধারিত হয়। কোনো পূর্বপুরুষে `policy` না থাকলে ডিফল্ট `"allow"`।

### ইনহেরিটেন্স নিয়ম

1. **Entry‑স্তরের policy**  
2. **Subsection‑স্তরের policy**  
3. **Section‑স্তরের policy**  
4. **ডিফল্ট `"allow"`**

### ওয়েবমাস্টারদের জন্য নির্দেশনা

- পুরো সাইট ingest‑যোগ্য করতে চাইলে কোথাও `policy` দেবেন না।  
- নিয়ন্ত্রণ চাইলে `"allow"`/`"forbid"` ব্যবহার করুন।  
- Section‑এ policy দিলে সব সন্তান তা ইনহেরিট করবে।

### AI সিস্টেমের প্রয়োজনীয়তা

- ইনহেরিটেন্স অনুযায়ী কার্যকর policy নির্ধারণ করতে হবে।  
- `"forbid"` মানে কঠোর নিষেধাজ্ঞা।  
- `"allow"` মানে ingest করার অনুমতি।

## কেন URL আবশ্যক

URL হলো কনটেন্টের canonical শনাক্তকারী। সারাংশ অর্থ দেয়, কিন্তু URL সেই অর্থকে ওয়েবের একটি নির্দিষ্ট, যাচাইযোগ্য অবস্থানের সাথে যুক্ত করে।

AI সিস্টেম URL ব্যবহার করে:

- ডিডুপ্লিকেশন  
- রিট্রিভাল  
- ভ্যালিডেশন  
- schema.org, sitemap, crawler‑এর সাথে ক্রস‑রেফারেন্স

## ক্যাটেগরিক্যাল প্রায়োরিটি কেন কার্যকর

| সুবিধা | ব্যাখ্যা |
|---|---|
| স্পষ্টতা | `"high"/"medium"/"low"` সর্বজনীনভাবে বোধগম্য। |
| সহজ | কোনো সংখ্যাগত স্কোরিং নয়। |
| ভ্যালিডেশন সহজ | ভুল ব্যবহার শনাক্ত করা যায়। |
| LLM‑বান্ধব | মডেলগুলো অভ্যন্তরীণভাবে ওজন নির্ধারণ করতে পারে। |

### Priority নির্দেশিকা

| মান | অর্থ |
|---|---|
| `"high"` | অত্যন্ত গুরুত্বপূর্ণ কনটেন্ট। |
| `"medium"` | অধিকাংশ কনটেন্টের জন্য ডিফল্ট। |
| `"low"` | কম গুরুত্বপূর্ণ বা পুরনো কনটেন্ট। |

## AI সিস্টেমের জন্য ভাষা কেন গুরুত্বপূর্ণ

LLMs ভাষা মেটাডেটা ব্যবহার করে:

- সঠিক tokenizer নির্বাচন করতে  
- সঠিক summarization মডেল প্রয়োগ করতে  
- embeddings‑এ ভাষা মিশ্রণ এড়াতে  
- রিট্রিভাল উন্নত করতে  
- বহুভাষিক hallucination কমাতে
