# مواصفة تنسيق ملف OLAMIP  
*حقوق النشر © 2025 رالف غونزاليس – https://olamip.org*

## نظرة عامة

ملف OLAMIP (`/olamip.json`) هو مستند JSON منظم يقدّم ملخصات مُنسّقة لأهم الصفحات في موقعك الإلكتروني. تم تصميمه ليكون سهل القراءة من قبل نماذج اللغة الكبيرة (LLMs)، مما يمكّنها من فهم محتوى موقعك، وتحديد أولوياته، واستخدامه بدقة ووضوح.

## موقع الملف

يجب أن يكون ملف OLAMIP موجودًا في جذر النطاق:

`https://yourdomain.com/olamip.json`

## الإعلان عن موقع ملف OLAMIP

لضمان اكتشاف الملف من قبل أكبر عدد من الأنظمة، يجب إضافة كل من وسم `<link>` ووسم `<meta>` داخل قسم `<head>` في موقعك.

### الاكتشاف الأساسي: `<link rel="olamip">`

- ممارسة قياسية: تقوم برامج الزحف بفحص وسوم `<link>` للبحث عن موارد مثل canonical وsitemap.  
- مناسب للأنظمة: يعلن علاقة واضحة بين الصفحة وملف OLAMIP.  
- قابلية التشغيل البيني: يتوافق مع معايير الويب الحالية.

### الاكتشاف الاحتياطي: `<meta name="olamip-location">`

- سهل الفهم للمستخدمين.  
- متوافق مع الأدوات التي تعتمد على وسوم `<meta>`.  
- يعمل كخيار احتياطي إذا لم يدعم النظام `rel="olamip"`.

### لماذا استخدام الطريقتين معًا؟

- ضمان المستقبل: قد تعتمد الأنظمة المختلفة طرق اكتشاف مختلفة.  
- المرونة: إذا فشلت إحدى الطريقتين، تعمل الأخرى كبديل.  
- الوضوح: يقلل الالتباس حول موقع ملف OLAMIP.

### أفضل تطبيق

```html
<link rel="olamip" href="https://yourdomain.com/olamip.json">
<meta name="olamip-location" content="https://yourdomain.com/olamip.json">
```

## بنية الملف

يجب أن يحتوي ملف OLAMIP على:

- `protocol`  
- `version`  
- `identity`  
- `content`  
- `metadata`  

### البنية العامة

```json
{
  "protocol": "OLAMIP",
  "version": "1.0.0",
  "identity": { "...": "..." },
  "content": { "...": "..." },
  "metadata": { "...": "..." }
}
```

---

## كائن Identity

| الحقل | النوع | مطلوب | الوصف |
|---|---|---:|---|
| `name` | `string` | نعم | اسم الموقع أو المؤسسة. |
| `type` | `string` | نعم | نوع الكيان مثل: `company`، `blog`، `ecommerce`. |
| `canonical_description` | `string` | نعم | وصف مقروء للبشر. |
| `tags` | `array<string>` | لا | كلمات مفتاحية اختيارية. |

---

## كائن Content

يحتوي كائن `content` على:

- كائن `overview`  
- قائمة `sections`  
- يمكن أن تحتوي كل Section على `subsections`  
- يمكن أن تحتوي كل Section أو Subsection على `entries`  

### كائن Overview

| الحقل | النوع | مطلوب | الوصف |
|---|---|---:|---|
| `summary` | `string` | نعم | ملخص موجز لهدف الموقع. |

---

## كائن Section

تمثل Section فئة أو مجموعة من المحتوى.

### حقول Section

| الحقل | النوع | مطلوب | الوصف |
|---|---|---:|---|
| `title` | `string` | نعم | عنوان القسم. |
| `summary` | `string` | نعم | وصف محتوى القسم. |
| `url` | `string` | نعم | الرابط الكانوني للقسم. |
| `section_type` | `string` | نعم | تصنيف دلالي. |
| `policy` | `string` | لا | `"allow"` أو `"forbid"`. |
| `tags` | `array<string>` | لا | كلمات مفتاحية. |
| `priority` | `string` | لا | `"high"`، `"medium"`، `"low"`. |
| `published` | `string` | لا | تاريخ ISO‑8601. |
| `language` | `string` | لا | رمز لغة BCP‑47. |
| `entries` | `array<Entry>` | نعم | قائمة الإدخالات. |
| `subsections` | `array<Section>` | لا | الأقسام الفرعية. |

### القيم المسموح بها لـ `section_type`

| section_type | المعنى |
|---|---|
| `blog_category` | فئة مقالات مدونة. |
| `news_section` | قسم الأخبار. |
| `product_collection` | مجموعة منتجات أو خدمات. |
| `doc_category` | قسم الوثائق. |
| `research_category` | قسم الأبحاث. |
| `project_group` | مجموعة مشاريع أو أعمال. |
| `content_section` | قسم عام. |

---

## سلوك Policy وآلية الوراثة

يتحكم حقل `policy` في السماح أو منع أنظمة الذكاء الاصطناعي من معالجة المحتوى.

### قواعد الوراثة

1. سياسة على مستوى Entry  
2. إن لم توجد: سياسة Subsection  
3. إن لم توجد: سياسة Section  
4. إن لم توجد أي سياسة: القيمة الافتراضية `"allow"`

## الهيكل الهرمي متعدد المستويات

```text
content
└── sections[]
    ├── Section (المستوى 1)
    │     ├── entries[]
    │     └── subsections[]
    │           ├── Section (المستوى 2)
    │           │     ├── entries[]
    │           │     └── subsections[]
    │           │           └── Section (المستوى 3)
    │           │                 └── entries[]
    │           └── ...
    └── ...
```

## كائن Entry

Entry هو أصغر وحدة محتوى.

### حقول Entry

| الحقل | النوع | مطلوب | الوصف |
|---|---|---:|---|
| `title` | `string` | نعم | عنوان المحتوى. |
| `summary` | `string` | نعم | ملخص موجز. |
| `url` | `string` | نعم | رابط كانوني مطلق. |
| `content_type` | `string` | نعم | نوع المحتوى الدلالي. |
| `policy` | `string` | لا | `"allow"` أو `"forbid"`. |
| `tags` | `array<string>` | لا | كلمات مفتاحية. |
| `priority` | `string` | لا | `"high"`، `"medium"`، `"low"`. |
| `published` | `string` | لا | تاريخ ISO‑8601. |
| `language` | `string` | لا | رمز لغة BCP‑47. |
| `metadata` | `object` | لا | بيانات إضافية خاصة بالصفحة. |

### لماذا الروابط مطلوبة؟

لأنها:

- معرفات كانونية  
- ضرورية لإزالة التكرار  
- تساعد في التحقق  
- تُستخدم للمطابقة مع schema.org وملفات sitemap

## كائن Metadata

مثال:

```json
{
  "last_updated": "2026-01-21",
  "language": "ar",
  "source_url": "https://www.yourwebsite.com/",
  "copyright": "© 2026 Example"
}
```

## أولوية المحتوى

### القيم

| القيمة | المعنى |
|---|---|
| `"high"` | محتوى مهم جدًا. |
| `"medium"` | القيمة الافتراضية. |
| `"low"` | محتوى ثانوي أو محدود الأهمية. |

---

## دعم اللغات المتعددة

يمكن تحديد `language` على:

- مستوى الملف (داخل `metadata`)  
- مستوى القسم  
- مستوى الإدخال  

باستخدام رموز BCP‑47.

---

## قواعد التحقق العامة

| القاعدة | المتطلب |
|---|---|
| JSON صالح | بدون فواصل زائدة. |
| الحقول المطلوبة | يجب توفيرها. |
| الروابط الكانونية | يجب أن تكون مطلقة وثابتة. |
| الملخصات | أقل من 500 حرف. |
| الوسوم | كلمة واحدة، أحرف صغيرة. |

---

## تنسيق الوسوم

- أحرف صغيرة  
- كلمة واحدة  
- ASCII  
- استخدام الشرطات للكلمات المركبة  

أمثلة:

| المفهوم | الوسم الصحيح |
|---|---|
| تعلم الآلة | `machine-learning` |
| علم البيانات | `data-science` |

---

## إصدار OLAMIP

- تتجاهل أدوات التحليل الحقول غير المعروفة.  
- يجب على الناشرين التحقق من صحة الملف وفقًا لأحدث مخطط.
