# المقدمة

يصف هذا المستند كيف يعمل بروتوكول **MCP** و**OLAMIP** و**OLAMIP-DELTA** معًا لتشكيل بنية موحدة لتقديم المحتوى القابل للفهم آليًا لأنظمة الذكاء الاصطناعي. وهو موجّه لمديري الويب ذوي الخبرة، ومتخصصي تحسين محركات البحث التقني، ومهندسي البنية التحتية المسؤولين عن المنصات المحتوى الكبيرة، وأنظمة التوثيق، والبيئات المؤسسية عالية الاعتمادية.

الفكرة الأساسية هي فصل **الاستدلال الدلالي** عن **الاسترجاع التشغيلي**. OLAMIP يصف الموقع بصورة منظمة يمكن للآلات قراءتها، بينما يتيح MCP للأنظمة الذكية الوصول إلى هذه البنية عبر أدوات قياسية، دون الحاجة إلى التخمين أو الزحف العشوائي.

---

# 1. نظرة مفاهيمية

تؤدي البروتوكولات الثلاثة أدوارًا متكاملة:

- **OLAMIP** يقدّم تمثيلًا دلاليًا منظمًا لبنية الموقع، وصفحاته، وملخصاته، وبياناته الوصفية، وسياساته.
- **OLAMIP-DELTA** يقدّم التغييرات التدريجية بحيث تبقى الأنظمة الذكية متزامنة دون إعادة معالجة الموقع بالكامل.
- **MCP** يوفّر طبقة التشغيل التي تسمح للوكلاء الذكيين بطلب بيانات OLAMIP واسترجاعها واستهلاكها عبر واجهة موحّدة ومستقلة عن التطبيق.

تسلسل المعالجة النموذجي يكون كالتالي:

```text
الموقع → OLAMIP → OLAMIP-DELTA → أدوات MCP → الأنظمة الذكية / خطوط RAG
```

هذه البنية تجعل الموقع قابلاً للفهم من منظور آلي، وفي الوقت نفسه قابلاً للتشغيل داخل بيئات LLM وأنظمة الاسترجاع المعتمدة على السياق.

# 3. OLAMIP: طبقة اللقطة الدلالية

يُعد `olamip.json` التمثيل المرجعي الموثوق للموقع. وهو لا يكتفي بإدراج الصفحات، بل ينظمها داخل بنية قابلة للاستهلاك الآلي.

يوفر OLAMIP عادةً ما يلي:

- بيانات الهوية: الاسم، النوع، والوصف canonical.
- البنية الهرمية: أقسام، أقسام فرعية، وعناصر.
- ملخصات محسنة للنماذج اللغوية.
- عناوين URL canonical لتثبيت الاستدلال.
- وسوم، ولغة، وإشارات أولوية.
- سياسات إدخال أو حظر صريحة.

## 3.1 الكائنات الأساسية

| الكائن | الغرض |
|---|---|
| Identity | يصف الموقع ككيان واحد. |
| Section | يجمع المحتوى المرتبط ضمن نطاق منطقي. |
| Subsection | تجميع متداخل بعمق غير محدود. |
| Entry | عنصر طرفي مثل صفحة، منتج، أو مستند. |

## 3.2 لماذا OLAMIP مهم

- يقلل الالتباس في تفسير LLM للمحتوى.
- يوفر ملخصات منظمة قابلة للاسترجاع.
- يدعم إعطاء الأولوية للمحتوى المهم.
- يتعامل مع المواقع متعددة اللغات بطريقة أكثر انضباطًا.
- يضيف تحكمًا صريحًا في سياسة الإدخال.

# 4. OLAMIP-DELTA: طبقة التحديثات التدريجية

`olamip-delta.json` يوفّر تحديثات يومية أو متحركة على اللقطة الأساسية، مما يسمح بتزامن فعال دون إعادة زحف الموقع.

## 4.1 عمليات الدلتا

| العملية | المعنى |
|---|---|
| added | إدخالات أو أقسام جديدة. |
| updated | تحديثات جزئية أو كاملة. |
| removed | حذف اعتمادًا على العنوان canonical. |

## 4.2 بنية الدلتا

```json
{
  "date": "YYYY-MM-DD",
  "added": [],
  "updated": [],
  "removed": []
}
```

## 4.3 نافذة متحركة مقابل دلتا مؤرشفة

| النمط | الوصف | الأنسب لـ |
|---|---|---|
| نافذة متحركة | ملف واحد يحتفظ بآخر N يوم من التغييرات. | أغلب المواقع. |
| مؤرشفة | ملف منفصل لكل يوم. | الناشرون ذوو الحجم العالي. |

## 4.4 قواعد الهوية

- العناوين canonical هي المعرّفات الأساسية.
- تغيير URL يستلزم حذفًا ثم إضافة جديدة.
- حذف قسم يزيل جميع العناصر التابعة له.

هذه القواعد تمنع التناقضات بين اللقطة الأساسية والتغييرات اللاحقة.

# 5. MCP: طبقة الاسترجاع والتكامل

يوفّر MCP واجهة التشغيل التي تسمح للأنظمة الذكية بطلب بيانات OLAMIP واستهلاكها عبر أدوات محددة.

## 5.1 لماذا نحتاج MCP

من دون MCP، تحتاج الأنظمة الذكية إلى:

- الزحف إلى الموقع.
- تحليل HTML.
- استنتاج البنية.
- تخمين المعنى.

أما مع MCP، فيمكنها:

- طلب `olamip.json` مباشرة.
- طلب `olamip-delta.json`.
- استرجاع أقسام أو عناصر محددة.
- تلقي التحديثات عند الطلب.
- إدخال OLAMIP داخل خطوط RAG بشكل حتمي.

## 5.2 بنية أدوات MCP

MCP لا يفرض أدوات جاهزة خاصة بـOLAMIP. بل يتيح لكل خادم أن يعرّف أدواته الخاصة حسب الحاجة. الأسماء التالية **أمثلة مقترحة** وليست جزءًا من مواصفة MCP نفسها.

أدوات مقترحة يمكن أن يعرّفها خادم MCP:

- `get_olamip_snapshot` → يعيد اللقطة الكاملة `olamip.json`.
- `get_olamip_delta` → يعيد `olamip-delta.json` الحالية.
- `resolve_url` → يجلب HTML الكامل لصفحة ما.
- `list_sections` → يسرد التسلسل الهرمي للأقسام.
- `get_entry` → يسترجع عنصرًا محددًا بواسطة URL canonical.

الفكرة هنا أن يتحول الموقع إلى **واجهة معرفة منظمة** بدل أن يكون هدفًا للزحف العشوائي.

## 5.3 تنفيذ خادم MCP لـOLAMIP

### 5.3.1 نظرة عامة على تدفق التنفيذ

```text
تعريف الأدوات → تنفيذ المعالجات → تسجيل الأدوات → نشر خادم MCP → اتصال الوكيل الذكي → إتاحة الأدوات
```

يمكن تنفيذ الخادم باستخدام:

- Python
- Node.js
- Go
- Rust
- Java
- أو أي بيئة قادرة على تشغيل عملية طويلة العمر

### 5.3.2 مخطط معماري: كيف تتفاعل أدوات MCP مع OLAMIP

```text
                 ┌──────────────────────────┐
                 │      خادم MCP            │
                 │  (تنفيذ مخصص)            │
                 └─────────────┬────────────┘
                               │
     ┌─────────────────────────┼─────────────────────────┐
     │                         │                         │
     ▼                         ▼                         ▼
┌──────────────┐       ┌──────────────┐         ┌────────────────┐
│ get_olamip_  │       │ get_olamip_  │         │ resolve_url    │
│ snapshot     │       │ delta        │         │ (جلب HTML)     │
└──────┬───────┘       └──────┬───────┘         └──────┬─────────┘
       │                      │                        │
       ▼                      ▼                        ▼
 [olamip.json]       [olamip-delta.json]        [HTML الموقع]
       │                      │                        │
       └──────────────┬──────┴──────────────┬─────────┘
                      ▼                     ▼
             ┌────────────────────────────────────┐
             │ الوكيل الذكي / خط RAG              │
             │ (يستخدم MCP للتأطير والاعتماد)     │
             └────────────────────────────────────┘
```

### 5.3.3 دليل تنفيذ خطوة بخطوة

### الخطوة 1 — تعريف الأدوات
الحد الأدنى الموصى به:

- `get_olamip_snapshot`
- `get_olamip_delta`
- `resolve_url`
- `list_sections`
- `get_entry`

### الخطوة 2 — تنفيذ كل أداة
كل أداة هي دالة خادم تستقبل مدخلات منظمة وتعيد مخرجات منظمة.

| الأداة | السلوك |
|---|---|
| get_olamip_snapshot | قراءة `olamip.json`. |
| get_olamip_delta | قراءة `olamip-delta.json`. |
| resolve_url | جلب HTML من عنوان canonical. |
| list_sections | تحليل OLAMIP وإرجاع الهيكل. |
| get_entry | البحث عن عنصر محدد بواسطة URL. |

### الخطوة 3 — تسجيل الأدوات
يجب تعريف:

- اسم الأداة.
- مخطط الإدخال.
- مخطط الإخراج.
- دالة المعالجة.

### الخطوة 4 — نشر خادم MCP
يمكن نشره داخل:

- خادم سحابي.
- حاوية.
- شبكة مؤسسية.
- خلفية CMS.
- خدمة صغيرة مستقلة.

### الخطوة 5 — اكتشاف الأدوات بواسطة الوكلاء
يتلقى الوكيل:

- قائمة الأدوات.
- الأسماء.
- الأوصاف.
- المخططات.

### 5.3.4 لماذا هذه البنية مهمة

عبر كشف OLAMIP من خلال أدوات MCP، يصبح موقعك API معرفة منظمًا بدل أن يكون هدفًا غير منظم للزحف. OLAMIP يقدّم الملخصات والعناوين canonical والوسوم والسياسات، بينما يتيح MCP استرجاع هذه البيانات بصورة تشغيلية قابلة للضبط.

بدلًا من البحث التخطيطي العشوائي، يعتمد الوكيل على:

- ملخصات منظمة.
- عناوين URL canonical.
- وسوم وتسلسل هرمي.
- دلتا للتحديثات التدريجية.

وعندما يحتاج النظام إلى التفاصيل الكاملة — مثل المواصفات التقنية أو النصوص القانونية أو التوثيق — يمكنه استدعاء أداة مثل `resolve_url` لجلب HTML الكامل. بهذا الشكل، يتولى OLAMIP الاكتشاف الدلالي، ويتولى MCP الاسترجاع العميق.

### عمليًا، هذه البنية تعني:

- لا زحف أعمى.
- لا استخراج معنى من HTML الخام فقط.
- لا تخمين في البنية.
- لا صفحات متوهمة.
- إمكانية استرجاع الصفحة الكاملة عند الحاجة.

# 6. سير العمل المشترك: كيف تستخدم الأنظمة الذكية MCP + OLAMIP

### المزامنة الأولية
- يسترجع MCP ملف `olamip.json`.
- يبني النظام الذكي فهرسًا دلاليًا كاملًا.

### المزامنة التدريجية
- يسترجع MCP ملف `olamip-delta.json`.
- يطبق النظام التحديثات بالترتيب الزمني.

### استرجاع المحتوى
- يجلب MCP HTML الكامل عند الحاجة.
- يستخدم النظام المحتوى في التضمين أو التلخيص أو الفهرسة.

### التكامل مع RAG
- ملخصات OLAMIP تغذي نماذج التضمين.
- العناوين canonical توفر تثبيتًا موثوقًا.
- الوسوم والأولوية توجه الترتيب في الاسترجاع.

### التحديث المستمر
- تحافظ الدلتا على التزامن.
- لا حاجة لإعادة زحف الموقع بالكامل.

# 8. أفضل الممارسات لمديري المواقع

- حافظ على ملف `olamip.json` نظيفًا وصحيحًا.
- أتمتة توليد الدلتا داخل CMS.
- اجعل الملخصات قصيرة ومركزة.
- استخدم عناوين canonical بشكل ثابت.
- لا تمنح أولوية عالية إلا للمحتوى الأكثر أهمية.
- استخدم رموز اللغة وفق معيار BCP-47.
- وحّد الوسوم باستخدام أحرف صغيرة وشرطات.

من المفيد أيضًا إضافة طبقة تحقق قبل نشر التغييرات، بحيث يتم فحص صحة البنية والروابط والاتساق بين اللقطة والدلتا. هذا يقلل الأخطاء التي قد تؤدي إلى إدخال سياق غير صحيح في الأنظمة الذكية.

---

# 9. الخلاصة

يشكّل MCP وOLAMIP معًا بنية مستقبلية لتقديم المحتوى بطريقة مناسبة للذكاء الاصطناعي. OLAMIP يوفّر الهيكل الدلالي، وOLAMIP-DELTA يوفّر التحديثات التدريجية، وMCP يوفّر واجهة التشغيل والاسترجاع.

النتيجة هي نظام يستطيع فهم المحتوى وفهرسته واسترجاعه بدقة عالية، دون الاعتماد على التخمين أو الزحف العشوائي أو الهلوسة. هذا هو الأساس العملي لموقع ويب جاهز للذكاء الاصطناعي.
