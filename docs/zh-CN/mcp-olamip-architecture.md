# 简介

本文档介绍 Model Context Protocol（MCP）与 OLAMIP / OLAMIP‑DELTA 如何协同工作，为 AI 系统提供统一、结构化、可解释的网站内容交付架构。适用于大型内容平台、文档系统、企业级网站的开发者、技术 SEO 和网站管理员。

---

# 1. 概念概览

MCP 与 OLAMIP 的角色如下：

- **OLAMIP**：提供网站内容的语义化结构、摘要、元数据与策略。  
- **OLAMIP‑DELTA**：提供每日或滚动的增量更新。  
- **MCP**：提供运行时协议，使 AI 系统能够以标准方式请求和消费 OLAMIP 数据。

整体流程：

```
网站 → OLAMIP → OLAMIP‑DELTA → MCP 工具 → AI 系统 / RAG 管道
```

# 3. OLAMIP：语义快照层

OLAMIP（`olamip.json`）是网站的权威语义结构表示，包含：

- 网站身份信息  
- 内容层级结构（Section / Subsection / Entry）  
- 面向 LLM 的摘要  
- 规范 URL  
- 标签、语言、优先级  
- 策略继承  

## 3.1 核心对象

| 对象       | 说明                         |
|------------|------------------------------|
| Identity   | 网站身份信息                 |
| Section    | 内容分组（如博客分类）       |
| Subsection | 无限层级嵌套                 |
| Entry      | 叶子节点（页面、产品、文档） |

## 3.2 OLAMIP 的重要性

- 消除 LLM 对内容的误解  
- 提供结构化摘要  
- 支持 AI 优先级策略  
- 支持多语言  
- 提供明确的内容允许/禁止策略  

---

# 4. OLAMIP‑DELTA：增量更新层

`olamip-delta.json` 提供每日或滚动更新。

## 4.1 Delta 操作类型

| 操作     | 含义               |
|----------|--------------------|
| added    | 新增内容或结构     |
| updated  | 内容部分或全部更新 |
| removed  | 按 URL 删除内容    |

## 4.2 Delta 结构

```json
{
  "date": "YYYY-MM-DD",
  "added": [...],
  "updated": [...],
  "removed": [...]
}
```

## 4.3 滚动窗口 vs 版本化 Delta

| 模式         | 描述                         | 适用场景         |
|--------------|------------------------------|------------------|
| 滚动窗口     | 一个文件包含最近 N 天更新    | 大多数网站       |
| 版本化 Delta | 每天一个文件                 | 高频更新网站     |

## 4.4 身份规则

- URL 是唯一标识符  
- URL 变更必须先删除再新增  
- 删除 Section 会删除其所有子节点

# 5. MCP：检索与集成层

MCP 是 AI 系统访问 OLAMIP 数据的运行时接口。

## 5.1 为什么需要 MCP

没有 MCP 时，AI 系统必须：

- 爬取网站  
- 解析 HTML  
- 推断结构  
- 猜测含义  

有了 MCP：

- 可直接请求 `olamip.json`  
- 可直接请求 `olamip-delta.json`  
- 可按需请求 Section 或 Entry  
- 可按需获取更新  
- 可将 OLAMIP 稳定集成到 RAG  

---

# 5.2 MCP 工具架构

⚠️ **重要说明：MCP 本身不包含任何 OLAMIP 工具。**  
以下工具名称是 **示例**，不是标准，也不是 MCP 内置功能。

示例工具：

- `get_olamip_snapshot` → 返回 `olamip.json`  
- `get_olamip_delta` → 返回 `olamip-delta.json`  
- `resolve_url` → 获取页面完整 HTML  
- `list_sections` → 列出内容层级结构  
- `get_entry` → 按 URL 获取特定 Entry  

这些名称是为了让 LLM 能够轻松理解其用途。

# 5.3 如何实现一个支持 OLAMIP 的 MCP 服务器

## 5.3.1 实现流程概览

```
定义工具 → 编写处理函数 → 注册工具 → 部署 MCP 服务器 → AI 自动发现工具
```

支持语言包括：

- Python  
- Node.js  
- Go  
- Rust  
- Java  
- 任何可运行常驻进程的环境

## 5.3.3 实现步骤详解

### **步骤 1：定义工具**

### **步骤 2：实现处理函数**

### **步骤 3：注册工具**

### **步骤 4：部署 MCP 服务器**

### **步骤 5：AI 自动发现工具**

## 5.3.4 为什么这种架构至关重要

OLAMIP 让 AI 无需爬取整个网站即可理解内容结构。  
MCP 允许在需要时获取完整 HTML。

优势包括：

- 无需盲目爬取  
- 无需通过 scraping 推断含义  
- 无需猜测结构  
- 无虚构页面  
- 仅在需要时获取完整内容  

**这确保 AI 能准确理解网站，同时在需要时访问完整内容。这正是“面向 AI 的 Web”的基础。**

# 8. 网站管理员最佳实践

- 保持 `olamip.json` 干净、有效  
- 在 CMS 中自动生成 Delta  
- 摘要保持在 500 字符以内  
- URL 规范化  
- “高优先级”内容不超过 5–10%  
- 使用 BCP‑47 语言代码  
- 标签统一小写、短横线格式

# 9. 结论

MCP + OLAMIP 构建了一个面向 AI 的未来内容交付架构。  
OLAMIP 提供语义结构；OLAMIP‑DELTA 提供增量更新；MCP 提供运行时接口。  
最终实现：AI 系统无需爬取即可准确理解、索引和检索内容。
