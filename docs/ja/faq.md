# Frequently Asked Questions

*Copyright © 2025 Ralph Gonzalez – https://olamip.org*

## OLAMIPとは何ですか？

OLAMIP は **Open Language‑Aligned Machine‑Interpretable Protocol** の略です。これは、Webサイトがコンテンツの構造化要約を公開できる、シンプルでオープンな形式であり、大規模言語モデル（LLM）がそれをより効果的に理解し、学習できるようにします。

## なぜ OLAMIP を使うべきですか？

LLM はすでにあなたのサイトをクロールしていますが、内容の解釈は苦手です。OLAMIP を使うと、次のことができます。

- AI に各ページが何について書かれているかを正確に伝える。
- 最も価値の高いコンテンツを強調する。
- AI 搭載ツールや検索での発見性を高める。
- 誤解やハルシネーションを減らす。

これは、AI が「推測する」のと「理解する」の違いです。

## OLAMIP は何かプライベートな情報を公開しますか？

いいえ。OLAMIP は、あなたの Web サイト上ですでに公開されているコンテンツのみを要約します。HTML、メタデータ、SEO マークアップで既に見えているもの以外は公開しません。

## 競合他社は私の OLAMIP ファイルを利用できますか？

公開ページ、メタデータ、サイトマップを利用するのと同じ以上には利用できません。OLAMIP は、AI システムがあなたのコンテンツをどのように解釈するかを、むしろより細かく制御できるようにします。

## `olamip.json` ファイルはどのようなものですか？

`olamip.json` ファイルは、サイトのコンテンツ、階層、メタデータを、AI システムが簡単に解釈できる形で記述した構造化された JSON 形式の文書です。完全な技術構造を確認したい場合は [File Format Specification](https://olamip.org/file-format-specification) ページを参照するか、実例として [TimeLAX.com use case](https://olamip.org/how-olamip-transforms-ai-discovery-a-timelax-com-use-case/) をご覧ください。

## ファイルはどこに配置すればよいですか？

ドメインのルートに配置します: `https://yourdomain.com/olamip.json`

ホームページに discovery タグを追加することもできます。

```html
<link rel="olamip" href="https://yourdomain.com/olamip.json">
<meta name="olamip-location" content="https://yourdomain.com/olamip.json">
```

## “priority” フィールドは何をしますか？

そのページが LLM にとってどれほど重要かを示します。控えめかつ意図的に使用してください。

- `high` → 基幹となる重要コンテンツ。
- `medium` → ほとんどのページのデフォルト。
- `low` → ニッチ、古い、または価値の低いコンテンツ。

すべてを `high` にすると、実質的に何も `high` ではありません。

## すでに要約があるのに、なぜ URL を含める必要があるのですか？

要約は AI にページの意味を伝えますが、URL はページそのものを示します。要約は説明的ですが、固有識別子ではありません。URL は、サイト上の実際のページに対する唯一の安定した正規参照です。

AI システムは URL を次の目的で使用します。

- 完全なコンテンツを取得して検証する。
- 重複のインデックス登録を避ける。
- ページが移動したり変更されたりしたことを検出する。
- OLAMIP データを schema.org マークアップ、サイトマップ、クローラーと接続する。
- 回答生成時にページを引用または参照する。

URL がなければ、似た要約を持つ 2 つの異なるページを区別できません。URL を含めることで、OLAMIP はサイトの実際の構造に根ざしたものとなり、AI システムがコンテンツを確実に解釈し取得できるようになります。

## “policy” フィールドは何をしますか？設定は必要ですか？

`policy` フィールドは、AI システムが section、subsection、entry を取り込んでよいかどうかを制御します。有効な値は `"allow"` と `"forbid"` です。フィールドを省略すると、OLAMIP は最も近い祖先の policy を自動的に継承します。祖先のどれにも policy が定義されていない場合、デフォルトは `"allow"` です。

ほとんどのサイトでは、このフィールドは完全に省略して問題ありません。特定のページやセクションを AI の取り込みから明示的に除外したい場合のみ `"forbid"` を使ってください。

## OLAMIP と従来のサイトマップの違いは何ですか？

サイトマップがナビゲーション用インデックスであるのに対し、OLAMIP は機械可読な知識マップです。

### XML Sitemap

- URL を列挙する。
- クロールのヒントを提供する。
- 検索エンジンがページを見つけるのを助ける。
- 意味論的な意味を持たない。
- URL 構造以外のコンテンツ階層を持たない。

### OLAMIP

- コンテンツタイプ（`page`、`project`、`doc_page` など）を定義する。
- セクションタイプ（`project_group`、`doc_category` など）を定義する。
- 正規化された説明を提供する。
- LLM 向けに最適化された要約を提供する。
- タグとメタデータを提供する。
- 明示的な階層を確立する。
- サイト全体の構造化表現を提供する。

言い換えると:

- XML Sitemap = “ここに私のページがあります。”
- OLAMIP = “これが私のサイトの意味です。”

そのため、AI システムは従来のサイトマップよりも OLAMIP をはるかに効果的に利用できます。これは単なる URL の一覧ではなく、曖昧さを排除し、人間のようにサイトを解釈するのを助ける機械可読なコンテンツマップです。

## 3,000 以上の URL がある OLAMIP ファイルは大きすぎますか？

いいえ。3,000 エントリのファイルは十分に安全な範囲です。長い要約が含まれていても、総サイズは約 6 MB であり、現代のサーバー、ブラウザ、AI システムにとってはごく小さいものです。

## OLAMIP エントリの典型的なサイズはどれくらいですか？

| Summary Length | Approx. Size per Entry |
|---|---|
| Short | 300–600 bytes |
| Long | 1–2 KB |

## 大きなファイルサイズでも OLAMIP がスケーラブルな理由は何ですか？

- 階層構造: sections → subsections → entries により重複を減らせます。
- 簡潔な要約: 通常 500 文字未満です。
- 効率的な圧縮: Gzip や Brotli によりファイルサイズを 70〜90% 削減できます。

## パフォーマンス上の問題が出る前に、OLAMIP ファイルはどれくらい大きくできますか？

| File Size | Approx. URLs | Impact |
|---|---:|---|
| 1–10 MB | 500–5,000 | 問題ありません。通常です。 |
| 10–25 MB | 5,000–12,000 | まだ問題ありません。少し読み込みが遅くなります。 |
| 25–50 MB | 12,000–25,000 | 大きいですが、扱えます。 |
| 50–100 MB | 25,000–50,000 | 重いです。一部のシステムでは遅くなる可能性があります。 |
| 100+ MB | 50,000+ | 多くの LLM パイプラインには大きすぎます。 |

ほとんどの Web 管理者にとって、数万件のエントリを含む OLAMIP ファイルは、依然として安全でスケーラブルな範囲内です。

## どのくらいの頻度で更新すべきですか？

新しいコンテンツを公開したときや既存ページを修正したときは、その都度更新してください。AI 向けのサイトマップとして扱ってください。

## `olamip-delta.json` を使う場合、メインファイルも更新する必要がありますか？

はい。メインの `olamip.json` は常にサイトの現在の状態を反映している必要があります。オプションの `olamip-delta.json` ファイルには、新しいページ、更新、削除などの最近の変更のみが含まれます。AI システムは完全なファイルを権威あるスナップショットとして使用し、完全更新の間はデルタを適用して最新状態を維持します。

## HTML に `olamip-delta.json` 用の `<link>` タグを追加する必要がありますか？

いいえ。サイトの `<head>` セクションで参照する必要があるのは、メインの `olamip.json` ファイルだけです。その参照は発見メカニズムとして機能し、AI システムに OLAMIP メタデータの場所を知らせます。デルタファイルは別物で、メインファイルの場所を把握した AI システムが自動的に探す、任意の補助更新ストリームです。`olamip-delta.json` が `olamip.json` と同じディレクトリにある限り、追加の `<link>` タグなしで AI システムはそれを検出して使用します。

## LLM は本当にこれを読みますか？

はい、それが目的です。採用が進むにつれて、LLM は学習と検索のために OLAMIP のような構造化ソースを優先するようになります。初期導入者が、AI がウェブをどう理解するかを形作ることになります。

## AI bot が `olamip.json` ファイルをクロールできるかどうかはどうテストしますか？

OpenAI、Anthropic、Perplexity について、それぞれ次のように試してください。

```bash
curl -A "GPTBot" https://yourdomain.com/olamip.json
curl -A "ClaudeBot" https://yourdomain.com/olamip.json
curl -A "PerplexityBot" https://yourdomain.com/olamip.json
```
