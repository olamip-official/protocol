# はじめに

本書は、Model Context Protocol（MCP）と OLAMIP / OLAMIP‑DELTA がどのように連携し、AI システム向けの統一された機械可読コンテンツ配信アーキテクチャを構築するかを説明します。大規模コンテンツプラットフォーム、ドキュメントシステム、エンタープライズウェブ基盤を扱うウェブ管理者・技術 SEO・開発者を対象としています。

---

# 1. コンセプト概要

MCP と OLAMIP は補完的な役割を果たします：

- **OLAMIP**：サイトのセマンティック構造、要約、メタデータ、インジェストポリシーを提供  
- **OLAMIP‑DELTA**：サイト全体を再処理せずに同期を維持するためのインクリメンタル更新  
- **MCP**：AI システムが OLAMIP データを標準化された方法で取得するための実行プロトコル  

全体のパイプライン：

```
Website → OLAMIP → OLAMIP‑DELTA → MCP Tools → AI Systems / RAG Pipelines
```

# 3. OLAMIP：セマンティックスナップショット層

OLAMIP（`olamip.json`）は、サイトの完全なセマンティック構造を表す機械可読スナップショットです。

含まれる内容：

- サイトの識別情報  
- 階層構造（Section / Subsection / Entry）  
- LLM 最適化要約  
- カノニカル URL  
- タグ、言語、優先度  
- インジェストポリシー  

## 3.1 コアオブジェクト

| オブジェクト | 説明                                 |
|--------------|--------------------------------------|
| Identity     | サイトの識別情報                     |
| Section      | 関連コンテンツのグループ             |
| Subsection   | 無制限の入れ子構造                   |
| Entry        | 最終コンテンツ（ページ・商品など）   |

## 3.2 OLAMIP が重要な理由

- LLM の誤解釈を防ぐ  
- 構造化された要約を提供  
- AI 対応のコンテンツ優先度設定  
- 多言語サイトをサポート  
- 明確なインジェスト制御

# 4. OLAMIP‑DELTA：インクリメンタル更新層

`olamip-delta.json` は日次またはローリング更新を提供します。

## 4.1 Delta 操作

| 操作     | 意味                     |
|----------|--------------------------|
| added    | 新規追加                 |
| updated  | 部分または全体更新       |
| removed  | カノニカル URL による削除 |

## 4.2 Delta 構造

```json
{
  "date": "YYYY-MM-DD",
  "added": [...],
  "updated": [...],
  "removed": [...]
}
```

## 4.3 ローリングウィンドウ vs バージョン管理 Delta

| モード             | 説明                               | 適用対象             |
|--------------------|------------------------------------|----------------------|
| ローリングウィンドウ | 過去 N 日分の更新を 1 ファイルに   | 一般的なサイト       |
| バージョン管理 Delta | 1 日 1 ファイル                    | 大規模更新サイト     |

## 4.4 識別ルール

- URL はカノニカル識別子  
- URL 変更は remove → add  
- Section 削除は子要素も削除

# 5. MCP：取得および統合レイヤー

MCP は AI システムが OLAMIP データを取得するための実行インターフェースです。

## 5.1 MCP が必要な理由

MCP がない場合、AI システムは：

- サイトをクロール  
- HTML を解析  
- 構造を推測  
- 意味を推測  

MCP がある場合：

- `olamip.json` を直接取得  
- `olamip-delta.json` を直接取得  
- 特定の Section / Entry を取得  
- 更新をオンデマンドで取得  
- RAG に確 deterministically 統合  

---

# 5.2 MCP ツールアーキテクチャ

⚠️ **重要：MCP は OLAMIP 用のツールを内蔵していません。**  
以下は **例示** であり標準ではありません：

- `get_olamip_snapshot`  
- `get_olamip_delta`  
- `resolve_url`  
- `list_sections`  
- `get_entry`  

これらは LLM が理解しやすいように設計された名前です。

# 5.3 OLAMIP 対応 MCP サーバーの実装

## 5.3.1 実装フロー概要

```
ツール定義 → ハンドラー実装 → ツール登録 → MCP サーバー展開 → AI が自動検出
```

## 5.3.2 MCP と OLAMIP の相互作用図

```
                 ┌──────────────────────────┐
                 │        MCP サーバー      │
                 │     （カスタム実装）     │
                 └─────────────┬────────────┘
                               │
     ┌─────────────────────────┼─────────────────────────┐
     │                         │                         │
     ▼                         ▼                         ▼
┌──────────────┐       ┌──────────────┐         ┌────────────────┐
│ get_olamip_  │       │ get_olamip_  │         │ resolve_url    │
│ snapshot     │       │ delta        │         │ （HTML 取得）  │
└──────┬───────┘       └──────┬───────┘         └──────┬─────────┘
       │                      │                        │
       ▼                      ▼                        ▼
 [olamip.json]       [olamip-delta.json]        [ウェブページ HTML]
       │                      │                        │
       └──────────────┬──────┴──────────────┬─────────┘
                      ▼                     ▼
             ┌────────────────────────────────────┐
             │ AI システム / RAG パイプライン     │
             └────────────────────────────────────┘
```

## 5.3.3 ステップバイステップ実装ガイド

### ステップ 1 — ツール定義  
### ステップ 2 — ハンドラー実装  
### ステップ 3 — ツール登録  
### ステップ 4 — MCP サーバー展開  
### ステップ 5 — AI による自動検出  

## 5.3.4 このアーキテクチャが重要な理由

OLAMIP により、AI はサイト全体をクロールせずに構造を理解できます。  
MCP により、必要な場合のみ完全 HTML を取得できます。

利点：

- ブラインドクロール不要  
- 意味理解のためのスクレイピング不要  
- 推測不要  
- 架空 URL なし  
- 完全 HTML は必要時のみ  

**これにより、AI システムは正確にサイトを理解し、必要に応じて完全なコンテンツにアクセスできます。これこそが「AI 対応ウェブ」の基盤です。**

# 8. ウェブ管理者向けベストプラクティス

- `olamip.json` を常に整合性のある状態に保つ  
- CMS で Delta 生成を自動化  
- 要約は 500 文字以内  
- カノニカル URL を一貫して使用  
- 「高優先度」は全体の 5–10% に制限  
- BCP‑47 言語コードを使用  
- タグは小文字・ハイフン区切りで統一  

---

# 9. まとめ

MCP と OLAMIP は、AI に最適化された未来志向のコンテンツ配信アーキテクチャを構築します。  
OLAMIP はセマンティック構造を、OLAMIP‑DELTA は更新を、MCP は実行インターフェースを提供します。  
その結果、AI システムはクロールなしで正確にコンテンツを理解・索引・取得できます。
