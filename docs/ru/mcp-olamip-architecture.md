# Введение

Этот документ описывает, как Model Context Protocol (MCP) и OLAMIP / OLAMIP‑DELTA работают вместе, формируя единую архитектуру доставки веб‑контента, понятного для систем искусственного интеллекта. Документ предназначен для опытных веб‑мастеров, технических SEO‑специалистов и разработчиков, работающих с крупными контент‑платформами, системами документации и корпоративными веб‑инфраструктурами.

---

# 1. Концептуальный обзор

MCP и OLAMIP выполняют взаимодополняющие функции:

- **OLAMIP** предоставляет структурированное семантическое описание сайта: иерархию, резюме, метаданные и политики.  
- **OLAMIP‑DELTA** обеспечивает инкрементальные обновления без необходимости пересканирования всего сайта.  
- **MCP** предоставляет протокол выполнения, через который ИИ‑системы запрашивают и получают данные OLAMIP.

Общий конвейер:

```
Сайт → OLAMIP → OLAMIP‑DELTA → Инструменты MCP → ИИ‑системы / RAG‑движки
```

# 3. OLAMIP: Семантический слой снимка

OLAMIP (`olamip.json`) — это авторитетное, машиночитаемое представление сайта. Оно включает:

- Метаданные идентичности  
- Иерархию контента  
- Резюме, оптимизированные для LLM  
- Канонические URL  
- Теги, язык, приоритеты  
- Политики наследования  

## 3.1 Основные объекты

| Объект     | Назначение                         |
|------------|------------------------------------|
| Identity   | Описание сайта как сущности        |
| Section    | Группа связанного контента         |
| Subsection | Вложенные группы без ограничений   |
| Entry      | Конечный элемент (страница, товар) |

## 3.2 Почему OLAMIP важен

- Устраняет неоднозначность для LLM  
- Предоставляет структурированные резюме  
- Позволяет задавать приоритеты для ИИ  
- Поддерживает мультиязычность  
- Обеспечивает контроль индексации

# 4. OLAMIP‑DELTA: Слой инкрементальных обновлений

`olamip-delta.json` предоставляет ежедневные или скользящие обновления.

## 4.1 Операции Delta

| Операция | Значение                     |
|----------|------------------------------|
| added    | Новые элементы               |
| updated  | Частичные или полные обновления |
| removed  | Удаление по каноническому URL |

## 4.2 Структура Delta

```json
{
  "date": "YYYY-MM-DD",
  "added": [...],
  "updated": [...],
  "removed": [...]
}
```

## 4.3 Скользящее окно vs версионированные Delta

| Режим             | Описание                               | Подходит для            |
|-------------------|------------------------------------------|--------------------------|
| Скользящее окно   | Один файл с последними N днями           | Большинство сайтов       |
| Версионированные  | Один файл на день                        | Крупные издатели         |

## 4.4 Правила идентичности

- URL — канонический идентификатор  
- Изменение URL требует remove‑then‑add  
- Удаление раздела удаляет все дочерние элементы

# 5. MCP: Слой извлечения и интеграции

MCP — это интерфейс выполнения, через который ИИ‑системы запрашивают OLAMIP‑данные.

## 5.1 Зачем нужен MCP

Без MCP ИИ‑системы должны:

- Сканировать сайт  
- Парсить HTML  
- Выводить структуру  
- Догадываться о значении  

С MCP они могут:

- Запрашивать `olamip.json`  
- Запрашивать `olamip-delta.json`  
- Получать конкретные разделы и записи  
- Получать обновления по требованию  
- Интегрировать OLAMIP в RAG‑конвейеры  

---

# 5.2 Архитектура инструментов MCP

⚠️ **Важно: MCP не содержит встроенных инструментов для OLAMIP.**  
Следующие имена — **предлагаемые примеры**, а не стандарт:

- `get_olamip_snapshot`  
- `get_olamip_delta`  
- `resolve_url`  
- `list_sections`  
- `get_entry`  

Они выбраны, потому что легко интерпретируются LLM.

# 5.3 Реализация MCP‑сервера для OLAMIP

## 5.3.1 Общий процесс реализации

```
Определить инструменты → Реализовать обработчики → Зарегистрировать инструменты → Развернуть MCP‑сервер → ИИ автоматически обнаруживает инструменты
```

## 5.3.2 Архитектурная схема взаимодействия MCP и OLAMIP

```
                 ┌──────────────────────────┐
                 │       MCP‑сервер         │
                 │   (кастомная реализация) │
                 └─────────────┬────────────┘
                               │
     ┌─────────────────────────┼─────────────────────────┐
     │                         │                         │
     ▼                         ▼                         ▼
┌──────────────┐       ┌──────────────┐         ┌────────────────┐
│ get_olamip_  │       │ get_olamip_  │         │ resolve_url    │
│ snapshot     │       │ delta        │         │ (полный HTML)  │
└──────┬───────┘       └──────┬───────┘         └──────┬─────────┘
       │                      │                        │
       ▼                      ▼                        ▼
 [olamip.json]       [olamip-delta.json]        [HTML страницы]
       │                      │                        │
       └──────────────┬──────┴──────────────┬─────────┘
                      ▼                     ▼
             ┌────────────────────────────────────┐
             │ ИИ‑система / RAG‑конвейер          │
             └────────────────────────────────────┘
```

## 5.3.3 Пошаговое руководство

### Шаг 1 — Определить инструменты  
### Шаг 2 — Реализовать обработчики  
### Шаг 3 — Зарегистрировать инструменты  
### Шаг 4 — Развернуть MCP‑сервер  
### Шаг 5 — ИИ автоматически обнаруживает инструменты  

## 5.3.4 Почему эта архитектура важна

OLAMIP устраняет необходимость сканирования сайта для понимания структуры.  
MCP позволяет получать полный HTML только при необходимости.

Преимущества:

- Нет слепого сканирования  
- Нет scraping для понимания смысла  
- Нет догадок  
- Нет вымышленных страниц  
- Полный HTML — только по запросу  

**Это обеспечивает точное понимание сайта ИИ‑системами и доступ к полному контенту при необходимости. Это и есть основа веба, готового для ИИ.**

# 8. Лучшие практики для веб‑мастеров

- Поддерживайте `olamip.json` в чистом и валидном состоянии  
- Автоматизируйте генерацию Delta  
- Держите резюме < 500 символов  
- Используйте канонические URL  
- Высокий приоритет — не более 5–10% контента  
- Используйте языковые коды BCP‑47  
- Нормализуйте теги (строчные, через дефис)  

---

# 9. Заключение

MCP и OLAMIP создают архитектуру доставки контента, оптимизированную для ИИ.  
OLAMIP обеспечивает семантическую структуру; OLAMIP‑DELTA — обновления; MCP — интерфейс выполнения.  
В результате ИИ‑системы могут точно понимать, индексировать и извлекать контент без сканирования и догадок.
